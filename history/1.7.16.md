# 版本 1.7.16 更新日志

**发布日期**: 2026-06-29

## 修复内容

### 删除过度设计的死代码（安全清理）

**问题描述**：
- 仓库存在一整层 `platform/` 服务框架（事件总线 / 存储 / 日志 / 服务工厂），在三个启动文件中被实例化，但从未被任何代码读取消费，唯一的 `bus.emit('run:start')` 没有任何监听者。
- 存在与 ESM 加载链重复的死加载器 `gameEntry.js`（脚本标签方式），无人引用。
- 存在 40KB 的 `css/styles.css`，无任何引用（实际生效的是 `home.css` 与 `index.css` 的 `@import` 链）。
- 存在多个仅 `export {}` 的占位桩文件。
- 存在无人导入的 `ui/runtime/events.js` 事件委托工具。
- `GameSession` 类仅包裹一个 3 行的 `start()`，且其 `pause()`/`resume()` 无任何调用者。

**实现方案**：
1. 删除整个 `js/platform/` 目录（services.js / eventBus.js / storage.js / logger.js）及空目录。
2. 删除 `js/shared/constants.js`（EVT 常量，仅被已删除的 services 链使用）及空目录。
3. 删除 `js/app/GameSession.js`，将其 `start()` 逻辑内联进 `js/app/bootGame.js`。
4. 删除死加载器 `js/gameEntry.js`。
5. 删除桩文件 `js/main.js`、`js/homeEntry.js`、`js/leaderboardEntry.js`。
6. 删除无人引用的 `js/ui/runtime/events.js`。
7. 删除无引用的 `css/styles.css`。
8. 清理 `bootGame.js` / `homePage.js` / `leaderboardPage.js` 中对 `createServices` 的死调用，并顺手修复后两者 catch 日志中的乱码中文。

**修改文件**：
- 删除：js/platform/（整层）、js/shared/constants.js、js/app/GameSession.js、js/gameEntry.js、js/main.js、js/homeEntry.js、js/leaderboardEntry.js、js/ui/runtime/events.js、css/styles.css
- 修改：js/app/bootGame.js、js/app/homePage.js、js/app/leaderboardPage.js、version.txt、package.json

**验证**：
- 全局扫描已删模块无残留 import 引用。
- `node --check` 三个改动文件语法通过。
- 浏览器加载主页：ESM 模块图全部解析成功，模板加载正常，标题中文显示正常（编码无损）；剩余仅为 `@supabase/supabase-js` 裸模块说明符报错，属需 vite 构建解析的预存在情况，与本次删除无关。
